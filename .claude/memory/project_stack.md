Kanary Boards is a kanban board app. Key stack facts:

**Runtime:** Deno 2.x (not Node.js). Package manager is `deno install`. Tasks run via `deno run --allow-all astro <cmd>`. Scripts defined in `deno.jsonc`. Unstable APIs enabled via `"unstable": ["kv"]` in deno.jsonc.

**Framework:** Astro 7.x with the Deno adapter (`@deno/astro-adapter`). SSR mode (`output: "server"`). Deploys to Deno Deploy. Pages: `src/pages/index.astro` (marketing homepage with the demo board), board pages under `src/pages/dashboard/` (`index.astro`, `task/`, `row/`). Shared layout at `src/layouts/BaseLayout.astro`. Middleware at `src/middleware.ts` (sets `boardId` cookie and `Astro.locals.boardId`).

**Routing:** react-router-dom 7.x inside the React island. `src/lib/dashboard/spa-router.ts` builds a data router (`createBrowserRouter`) whose routes all render `BoardView`; `BoardController` (the `client:only` island mounted by `SPA.astro`) renders `<RouterProvider>` inside `BoardProvider` and routes drawer `a[data-board-link]` clicks through `router.navigate`. Board routes live under `/dashboard` (`/dashboard`, `/dashboard/task/:taskId`, `/dashboard/row/:rowId`). Astro handles SSR for both; react-router handles client-side navigation.

**UI:** React 19. Components live in `src/components/`, split by framework: React (`.tsx`/`.ts`, including the board context state) under `react/`, Astro (`.astro`) under `astro/`. State is managed with Context API + useReducer (no Redux/Zustand). Many fine-grained contexts in `BoardContext.tsx` (see [[State architecture and types]]). Icons via `@iconify-json/{hugeicons,basil,mingcute}` + `@iconify/tailwind4`. Rich text via `@lyfie/luthor`.

**Styling:** Tailwind CSS 4.x + DaisyUI 5.x. Uses `className=` (React convention). Two themes: `kanary-day` (light) and `kanary-night` (dark), toggled via ThemeToggle.tsx.

**AI:** Google GenAI SDK (`@google/genai`) via a POST endpoint at `src/pages/api/v1/ai/task-titles.ts`. Generates task titles and checklist items.

**Persistence:** Deno KV (migrated from localStorage). KV utilities in `src/lib/db/kv.ts`. Board stored as one entry per entity at `["row"|"column"|"task", boardId, id]` plus a `["board_rev", boardId]` revision key (legacy `["board", boardId]` blobs are migrated on read), task comments at `["task_comment", boardId, taskId, commentId]` (no `task_meta`). API routes all under `src/pages/api/v1/` (`board.ts`, `board/events.ts`, `tasks/[id]/comments/`, `cron/purge-trash.ts`, `ai/task-titles.ts`, `contact-messages.ts`, `test-data.ts`, plus the CLI routes) — see [[url-routing-and-kv]]. `BoardProvider` delegates to `context/effects/useBoardPersistence.ts`, which fetches on mount, saves only what changed with a 500ms debounce (checked against the board revision; a 409 is merged and resent), auto-migrates any existing localStorage data to KV on first load, refreshes live over SSE, and syncs the board across same-browser tabs (see [[State architecture and types]]).

**boardId:** A UUID generated by Astro middleware on first visit, stored as a cookie (`boardId`), available server-side as `Astro.locals.boardId` and passed as a prop to the React island. Designed for future multi-user support.

**Type checking:** `deno run --allow-all astro check` — passes clean with exit 0.

**Lock file:** `deno.lock` (do not manually edit).
