Kanary Boards (kanby.ai) is a kanban board app. Key stack facts:

**Runtime (local/CI tooling):** Deno 2.x (not Node.js). Package manager is `deno install`. Tasks defined in `deno.jsonc`, run via `deno run --allow-all astro <cmd>`. Note the *deployed* runtime is `workerd`, not Deno — see below.

**Framework:** Astro 7.x with the **Cloudflare adapter** (`@astrojs/cloudflare` v14). SSR mode (`output: "server"`). **Deploys to Cloudflare Workers** (migrated from Deno Deploy on 2026-07-30; `@deno/astro-adapter` is gone). Worker config in `wrangler.jsonc`. Middleware at `src/middleware.ts`. Local production-runtime preview: `deno task preview:cf` (`wrangler dev`).

Two `wrangler.jsonc` details that are load-bearing:
- `compatibility_date` must be a date the **installed** `workerd`/`miniflare` supports. Setting it ahead of the local binary breaks builds and prerendering with a "newest date supported" startup error.
- `compatibility_flags` includes `nodejs_compat` because `@clerk/astro` imports `node:fs`, `node:path` and `node:async_hooks`.

**Routing:** react-router-dom 7.x inside the React island; Astro handles SSR.

**UI:** React 19, components in `src/components/`. Context API + useReducer (no Redux/Zustand): `BoardStateContext`, `BoardDispatchContext`, `BoardRefsContext`. Icons via `astro-icon` + `@iconify/json` + `@iconify/tailwind4`. Rich text via `@lyfie/luthor`.

**Styling:** Tailwind CSS 4.x + DaisyUI 5.x, `className=`. Themes `kanary-day` / `kanary-night`.

**AI:** Google GenAI SDK (`@google/genai`) via `src/pages/api/generate-tasks.ts`.

**Persistence:** **Cloudflare Workers KV** (was Deno KV). Utilities in `src/lib/db/kv.ts` — functions take a `KVNamespace` as their first parameter rather than using a module-level singleton. See [[project_url_routing_kv]].

**Env/secrets access:** server-side secrets come from `import { env } from "cloudflare:workers"`. **Not** `Astro.locals.runtime.env` — that throws in Astro 6+. See [[project_cloudflare_env_access]].

**Testing:** two vitest pools, because Worker code can't run in jsdom.
- `deno task vitest` → `vitest.config.ts`, jsdom, `tests/vitest/` (159 tests). Must filter `vite-plugin-cloudflare:*` plugins out of `getViteConfig()`'s result or the whole suite fails to start.
- `deno task vitest:workers` → `vitest.workers.config.ts`, `@cloudflare/vitest-pool-workers`, `tests/workers/` (72 tests) with real miniflare-simulated KV via `cloudflare:test`.

**Type checking:** `deno task astro check`. `worker-configuration.d.ts` is generated by `wrangler types` and gitignored — CI regenerates it in `static-analysis.yml`. `tests/workers/` has its own tsconfig (needs `@cloudflare/vitest-pool-workers/types`) and is excluded from the root one.

**Lock file:** `deno.lock` (do not manually edit).
